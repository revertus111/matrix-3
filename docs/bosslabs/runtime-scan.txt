Matrix3 BossLabs - Phase 1/2 runtime scan
2026-08-31

verified-static

1. NPC combat dispatch
- Server/src/main/java/com/rs/game/npc/combat/CombatScriptsHandler.java discovers normal CombatScript implementations from com.rs.game.npc.combat.impl at startup.
- Normal scripts are keyed by NPC id and/or NPC definition name through CombatScript.getKeys().
- Missing normal custom scripts fall back to Matrix3's existing Default combat script.
- The normal script cache is startup/static, so it is not sufficient by itself for BossLabs definitions that may later be registered/reloaded while the server is running.
- Phase 2 therefore adds one narrow BossLabs delegation check inside the existing CombatScriptsHandler. This is not a second dispatcher: registered BossLabs NPC ids delegate to BossCombatScript, while every unregistered NPC continues through the unchanged Matrix3 cached-script/default path.
- CombatScriptsHandler now exposes read-only resolved-script/default inspection methods using the same internal resolution path as live combat so BossLabs does not duplicate script-discovery semantics.

2. NPC combat execution
- Server/src/main/java/com/rs/game/npc/combat/NPCCombat.java owns target validation, clipping/range checks, movement/follow behavior, combat delay, and dispatch into CombatScriptsHandler.specialAttack().
- Server/src/main/java/com/rs/game/npc/combat/CombatScript.java already provides delayed-hit helpers and authoritative hit-chance/max-hit integration through Combat.getHitChance().
- Existing Default/ChaosElemental combat demonstrates Matrix3-owned animation, GFX, projectile, scheduled/delayed-hit paths.
- BossCombatScript reuses those same CombatScript/World helpers and does not bypass NPCCombat target/range/timing ownership.

3. NPC definitions/stats
- Server/src/main/java/com/rs/cache/loaders/NPCDefinitions.java owns cache-backed NPC id/name/model/size/combat-level/client-script data.
- Server/src/main/java/com/rs/game/npc/combat/NPCCombatDefinitions.java owns hitpoints, attack/defence/death animation data, projectile/GFX references, respawn delay, aggression, XP, and poison flags.
- Server/src/main/java/com/rs/utils/NPCCombatDefinitionsL.java is the current combat-definition loader/authority used for inspection without spawning a temporary NPC.
- Server/src/main/java/com/rs/utils/Utils.java already provides getNPCDefinitionsSize() using cache index 18 with the correct 128-file archive layout.
- NPC attack speed can be read from the same cache client-script key used by NPC.getAttackSpeed(), falling back to 4 when absent.

4. NPC lifecycle/spawning
- NPC construction initializes Matrix3 combat state, adds the NPC to World, updates its region, and loads map regions.
- NPC.processNPC()/NPCCombat own normal target/combat processing.
- NPC.sendDeath() owns death animation timing, XP, drop invocation, reset/finish, and respawn scheduling.
- Spawned NPCs can be marked so normal respawn is not scheduled after death.
- BossLabs does not change NPC.java or NPCCombat.java for the runtime adapter or NPC search/inspection foundation.

5. Drops
- NPC.drop() resolves loot through NPCDrops.getDrops(id), existing drop-rate/lootshare handling, Drops.generateDrops(), and NPC.sendDrop().
- BossLabs must reference/author data through this existing drop authority rather than add an alternate loot engine.

6. BossLabs content/runtime foundation
- com.rs.game.npc.bosslabs.BossAttackDefinition describes one combat style/presentation/tuning entry.
- com.rs.game.npc.bosslabs.BossPhaseDefinition describes one health-percentage band and its allowed attacks.
- com.rs.game.npc.bosslabs.BossDefinition describes one NPC-backed boss and resolves the active phase from current/max HP.
- com.rs.game.npc.bosslabs.BossDefinitionRegistry is a small thread-safe NPC-id -> immutable BossDefinition mapping. It owns no gameplay behavior.
- com.rs.game.npc.bosslabs.BossCombatScript is the Matrix3 CombatScript adapter for registered BossLabs definitions.
- BossCombatScript resolves current health -> active phase -> one configured attack, then uses existing Matrix3 CombatScript helpers for hit chance/damage and existing World projectile timing.
- Attack animation/GFX/projectile/max-hit/combat-delay fields may use BossAttackDefinition.USE_NPC_DEFAULT (-1) to inherit the existing NPC/cache value where supported.
- No BossLabs NPC id is registered by default in this slice. Existing live NPC behavior is therefore unchanged until first-boss content explicitly registers an id.

7. Unified NPC search / existing-boss inspection
- com.rs.game.npc.bosslabs.BossNpcSearchService provides one query path rather than separate id/name modes.
- All-digit input is treated as an NPC id and resolved directly through cache index 18; it does not build the full name index.
- Non-numeric input performs case-insensitive name matching across valid NPC definition files within Utils.getNPCDefinitionsSize().
- Name indexing is lazy/reused and supports explicit invalidation for future cache/import changes. The future Swing caller must build/refresh it away from the EDT.
- Search ranking is exact name first, prefix second, substring third; duplicate-name NPC ids remain separate results.
- com.rs.game.npc.bosslabs.BossNpcInspection auto-populates verified NPC/cache/combat fields plus combat source, resolved script class, and current BossLabs definition.
- Inspection is read-only and does not spawn NPCs, modify registrations, apply hits, mutate drops, or change world state.
- Existing hand-written Java bosses can be inspected and identified but are not automatically claimed as converted BossLabs phases/mechanics.
- docs/bosslabs/NPC_SEARCH.md records the detailed no-dropdown search/editor contract.
