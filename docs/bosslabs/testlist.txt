Matrix3 BossLabs - planned runtime acceptance list

Documentation-only baseline
1. Confirm docs/bosslabs/BOSSLABS.md remains subordinate to AGENTS.md, docs/rs3/PROJECT.md, and docs/client-console/CLIENT_CONSOLE.md.
2. Confirm BossLabs does not claim ownership of combat, NPC lifecycle, world state, drops, permissions, persistence, or other Matrix3 gameplay authorities.
3. Confirm new BossLabs work is driven by the first complete custom boss rather than speculative tool expansion.

Current Java foundation acceptance
4. Eclipse clean/build the Server with Java 8. Confirm BossAttackDefinition, BossPhaseDefinition, BossDefinition, BossDefinitionRegistry, BossCombatScript, BossNpcInspection, BossNpcSearchService, BossDefinitionStore, and BossDefinitionPublisher compile with the narrow CombatScriptsHandler hooks.
5. Construct a BossAttackDefinition with MELEE, RANGE, and MAGE values. Confirm valid styles are accepted and an unsupported style throws IllegalArgumentException.
6. Construct health phases such as 71-100, 31-70, and 0-30. Confirm BossDefinition accepts non-overlapping ranges and rejects overlapping phase ranges.
7. Confirm BossDefinition.getPhaseForHealth() resolves 100%, 70%, 30%, and 0% to the intended configured phase and clamps current HP above max/below zero safely.
8. Register and unregister a BossDefinition through BossDefinitionRegistry. Confirm lookup is keyed only by the definition NPC id and the immutable definition instance is returned unchanged.
9. With no BossLabs definition registered for an NPC id, confirm CombatScriptsHandler still resolves the same existing id/name/default CombatScript as before this patch.
10. With a test BossLabs definition registered for a safe test NPC id, confirm CombatScriptsHandler delegates attacks to BossCombatScript rather than the normal cached/default script.
11. Confirm BossCombatScript selects attacks only from the current health phase and preserves Matrix3 CombatScript accuracy/max-hit handling.
12. Confirm USE_NPC_DEFAULT (-1) attack animation/GFX/projectile/max-hit/combat-delay values inherit the existing NPC/cache-backed values where applicable.
13. Confirm ranged/magic BossLabs attacks use Matrix3 World.sendProjectileNew()/projectile timing and CombatScript.delayHit(), while melee uses the existing immediate delayed-hit helper path.
14. Confirm unregistering the test definition immediately returns that NPC id to the normal Matrix3 combat-script path without restarting the server.
15. Confirm BossLabs registry/adapter code does not spawn NPCs, select targets outside NPCCombat, alter pathing, replace death/respawn handling, load drop tables, or directly mutate loot ownership.
