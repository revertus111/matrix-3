2026-10-05 - Fix TP decomp-toolkit object-base layout after CISO runtime failure
- User runtime rerun with a supported `.ciso` proved automatic image discovery, MSYS2 Python/Ninja reuse, donor clone and pinned checkout all work.
- `dtk dol split` then failed with `orig/GZ2E01/files/RELS.arc not found`.
- Root cause: the builder created `orig/GZ2E01` as the disc-image file itself. The pinned TP config defines `object_base: orig/GZ2E01`, while decomp-toolkit treats that object base as a directory and searches for disc images inside it before exposing `sys/` and `files/` through its VFS.
- The builder now creates `orig/GZ2E01/` as a directory and places the donor image inside it with its original filename/extension, allowing decomp-toolkit to detect the CISO/RVZ/ISO container correctly.
- Reruns automatically repair the malformed local workspace from the previous builder by deleting only the builder-created `orig/GZ2E01` link/copy before creating the correct directory layout; the user's source image under Matrix3/native is untouched.
- Status: object-base fix is verified-static; donor build still needs one runtime rerun.
