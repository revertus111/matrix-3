Matrix3 Interface Editor V1.3 - targeted runtime acceptance

Quick path
1. Pull current `main`, clean/build Client in Eclipse/Java 8, then launch Matrix3 normally.
2. Open Client Console and click Interface Editor. Confirm the panel lazy-loads, stays dark/readable, scrolls normally, and Wire Mesh is OFF by default so the OpenGL canvas does not flash.
3. With Bank/Backpack interface 762 open, click `Load Active Interface`. Confirm the editor loads 762 rather than the permanent 1477 root/gameframe or a small helper interface.
4. Open the `Open now` dropdown. Confirm it lists currently attached runtime interfaces, marks the active entry with a dot, marks the root entry, and shows loaded component counts when available.
5. Choose one `Open now` entry. Confirm that interface loads immediately and its component list/inspector refreshes without needing to type an ID.
6. Click `Browse All Interfaces...`. Confirm a dark searchable browser opens, shows the current cache interface-ID range, marks OPEN/ACTIVE/ROOT entries, and does not block the game/client.
7. Search for `762`, double-click it, and confirm the browser closes and Interface Editor loads 762. Repeat once using `Load Selected` instead of double-click.
8. Search the browser for `open`, `active`, and `root`. Confirm those filters surface the expected runtime-marked entries.
9. Enter an explicit target such as `762:215` and press Enter/Load. Confirm exact interface:component targeting still works alongside the new browser workflow.
10. Confirm the selected inspector shows Type, Parent, Item ID, Children, Base geometry sliders, Runtime geometry sliders, Alignment X/Y/W/H, Text, and Sprite ID.
11. Confirm Slider range offers `Fine +/-64`, `Normal +/-256`, and `Wide +/-1024`, with Normal selected by default. Confirm `Live geometry` and `Pin runtime X/Y/W/H` are enabled by default.
12. Drag Runtime X on a harmless selected component slowly left/right. Confirm the actual component moves while dragging, the client remains responsive, and no Apply button is required.
13. Use Runtime X `-` and `+`. Confirm each click moves exactly one pixel and applies immediately.
14. Type an exact Runtime X value and press Enter. Confirm the slider recenters if needed and the exact value applies live. Repeat once using focus-loss apply.
15. Drag quickly for several seconds. Confirm the component settles on the final slider value without delayed old movements after release.
16. Click Reset Selected. Confirm the component returns to its exact pre-editor geometry and no pending slider update reapplies afterward.
17. Apply harmless changes to two components, then Reset Interface. Confirm both restore.
18. Click Copy Values and confirm clipboard output contains interface:component, type/parent, base geometry, runtime geometry, alignment, text, and sprite values.

Runtime-interface discovery checks
19. With Interface Editor open, close interface 762 in game. Confirm `Open now` removes 762 on the next refresh.
20. Reopen 762. Confirm it reappears and becomes the preferred active foreground interface.
21. Open a different substantial central interface. Confirm `Load Active Interface` follows the newly attached foreground interface; if several helper interfaces open at once, the larger/main interface should be preferred.
22. Confirm the permanent root/gameframe remains visible in `Open now` as ROOT but is not preferred over a newly opened substantial foreground interface.
23. Browse a closed interface ID from `Browse All Interfaces...`. Confirm it can still be inspected without pretending it is OPEN.

Wire Mesh carryover/regression
24. Leave Wire Mesh OFF during normal editor use and confirm there is no OpenGL black flashing.
25. Optional diagnostic only: enable Wire Mesh once and confirm the known AWT/OpenGL flashing behavior is still isolated to that overlay. Turn it back off. Do not treat this as a pass requirement; renderer-native overlay replacement is carryover.
26. With Wire Mesh OFF, confirm Pick Component is not used accidentally. If intentionally testing Pick Component, expect it to enable the current overlay path and treat any flashing as known carryover evidence rather than a new browser regression.

Generic/regression path
27. Load one unrelated interface through `Open now` and one through `Browse All`. Confirm component discovery/search and geometry editing remain generic and are not hardcoded to 762.
28. Type part of a component ID/type/text into Components search. Confirm filtering remains responsive.
29. Disable `Live geometry`, move a slider, and confirm no live write occurs until `Apply Exact / Visual` is pressed. Re-enable it and confirm live behavior resumes.
30. On a harmless text component, enable Override text, change it, click `Apply Exact / Visual`, then Reset Selected. Confirm override/restoration work.
31. Switch rapidly between Interface Editor and existing Client Console panels. Confirm lazy-panel behavior, collapse/reopen, and normal Client Console input remain intact.
32. Restart Client and confirm temporary interface overrides do not persist across restart.
33. Run one safe normal gameplay/input action after editor use. Confirm no server/gameplay authority changed.

Pass condition
- Interface Editor can discover the current foreground interface without typing an ID, exposes real currently attached interfaces, provides a searchable all-interface cache browser, retains live/reversible geometry editing, keeps Wire Mesh safely off by default after the verified OpenGL flashing issue, and does not change Matrix3 gameplay/server authority.
