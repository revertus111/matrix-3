2026-10-04 - Mario autonomous sleep bridge-stall fix
- Runtime diagnostics captured `bridgeReady=true` with a stale native frame (`frameAgeMs=4745`) and last action `0x0C000203`; libsm64 defines that action as `ACT_SLEEPING`.
- Updated `sm64_bridge` to keep the embedded Mario out of `ACT_START_SLEEPING` / `ACT_SLEEPING` and return him to normal `ACT_IDLE` before the next native tick.
- This fixes the proven long-idle transition at the native state boundary instead of extending Matrix renderer/suppression grace again.
- Normal idle, movement, jump, attack and crouch/ground-pound inputs are unchanged. A rebuilt `sm64_bridge.exe` is required for runtime verification.

2026-10-04 - Mario autonomous sleep bridge-stall fix v2
- Runtime flight-recorder evidence proved the first sleep guard did not actually prevent the active native stream from spending multiple seconds in `ACT_START_SLEEPING (0x0C400202)` before entering `ACT_SLEEPING (0x0C000203)`, after which sequence publication stopped and `SUPPRESS_RS` failed open at `frameAgeMs=1250`.
- Hardened `sm64_bridge.c` on both sides of `sm64_mario_tick`: inherited sleep state is repaired before a tick, and any tick that itself enters START_SLEEPING/SLEEPING is immediately reset to `ACT_IDLE` and re-ticked before its frame can be published.
- Added `[SM64 Bridge] sleep-guard-v2 active` on binary startup so the loaded executable is visibly distinguishable from a stale pre-fix build.
- Matrix renderer freshness and local-player suppression thresholds were intentionally left unchanged; this patch targets the native frame-stall cause directly.
