Matrix3 server startup test list

1. Windows Explorer path
   - Open the real Server folder in Windows File Explorer.
   - Double-click run_game.bat.
   - A MATRIX3 - GAME SERVER console opens and Gradle :runGame starts successfully.
   - Local embedded login core starts as part of normal non-hosted GameLauncher startup.
   - No historical stack-map/verifier failure appears from bypassing the Gradle path.

2. Eclipse green Run path
   - Pull and refresh the Matrix3-Server project.
   - Open Run Configurations -> Java Application.
   - Select the shared configuration named Matrix3 Server.
   - Run it once.
   - com.rs.Matrix3Startup exits quickly after opening a separate MATRIX3 - GAME SERVER command window.
   - Closing/stopping the tiny Eclipse launcher after it exits does not own or terminate the detached server console.
   - The separate console continues Gradle :runGame normally.
   - The normal green Run button can reuse Matrix3 Server from Run history afterward.

3. Safety
   - Do not use the raw Java Application configuration for com.rs.GameLauncher for normal development startup.
   - Do not run run_login.bat separately during normal local :runGame startup because GameLauncher already starts the embedded local login core.
   - Double-clicking run_game.bat inside Eclipse only opens the text editor; double-click execution is done from Windows File Explorer.
