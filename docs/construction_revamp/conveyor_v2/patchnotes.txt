2026-10-03 - Conveyor V2.0 one-tile repeated visual module
- Runtime screenshots rejected the stretch/fixed visual strategy: as straight runs became longer, the stretched belt surface drifted visibly away from rollers/rails and several authored details began to distort.
- ConveyorRunPreview now treats the complete visible authored straight assembly as one module instead of stretching selected roles across the logical run.
- The authored module is normalized once to exactly 512 model units along its long axis, then cloned once per logical conveyor tile at exact 512-unit intervals.
- Module copies use Matrix3's Class159 merge constructor so the source face, texture and UV structures stay attached to each intact module; all repeated modules are then merged into one generated raw and one cached renderer Model per straight segment.
- One logical SettlementConveyorRun remains the server/persistence/transport owner. No per-tile Construction objects, scene registrations, collision entries or save records were introduced.
- Live Model Editor conveyor roles currently act as inclusion/exclusion for the straight module; the old role-specific belt stretch, endpoint-cap spreading, repeat-detail spacing and automatic support-spacing renderer paths are superseded for straight belts.
- The hardcoded fallback authored assembly uses the same one-tile module pipeline after a fresh client launch when no live editor recipe has been applied.
- V2.0 payload interpolation, belt-to-belt connection metadata, backpressure, physical inventory ownership and server transport are unchanged.
- Custom CORNER_1T / splitter / merger visuals remain later client presentation driven by the existing server-owned connection graph.
- Status: IMPLEMENTED / NEEDS RUNTIME TEST.

2026-10-03 - Conveyor V2.0 per-segment axis lock correction
- Runtime video showed the straight preview re-evaluating dominant X/Y movement on every hover update, causing the entire belt to snap repeatedly between horizontal and vertical as the cursor crossed the diagonal threshold.
- Each authored segment now chooses E/W or N/S from the first meaningful movement after its Point A and keeps that axis locked until Point B is committed or the chain is cancelled.
- Committing Point B still promotes B to the next Point A, but the next chained segment receives a fresh axis lock so 90-degree turns remain intentional.
- Moving only perpendicular to the locked axis clears the zero-length preview instead of flipping the belt orientation; status text explains the active lock.
- Right-click/Escape clears both the retained chain anchor and its current axis lock.
- Server transport graph, persistence schema, payload ownership, backpressure, chest/machine endpoints and custom corner visuals are unchanged.
- Status: IMPLEMENTED / NEEDS RUNTIME RETEST.

2026-10-03 - Conveyor V2.0 continuous-chain placement correction
- Runtime screenshot verified straight-only run creation, but exposed a UX regression: each successful A->B commit cleared the client Point A, so the tool required a fresh start click instead of continuing from the just-placed endpoint.
- Successful placement now promotes projected Point B to the next Point A; repeated endpoint clicks author A->B->C->D straight runs without reselecting every seam.
- Right-click/Escape clears the retained chain anchor and returns the still-armed Conveyor tool to a fresh Point A.
- Server connection behavior is unchanged and was reverified statically: an existing straight source ending on the new run start resolves insertion distance 0 and persists source->receiver linkage.
- Retained placement state uses a Conveyor-local immutable coordinate anchor because ConstructionPlacementController.HoverTile construction remains private to its world-tile picker owner.
- No payload transport, SettlementState schema, chest/machine ownership, connection graph, renderer, or custom corner visual changed.
- Status: IMPLEMENTED / NEEDS RUNTIME RETEST.
