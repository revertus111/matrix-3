RS3 CacheEditor foundation test list

[ ] In Eclipse with Java 8, run com.rs.tools.cacheeditor.CacheEditorLauncher as a Java Application.
[ ] Select the revision-830 cache directory and confirm the editor opens without starting the game server.
[ ] Raw Cache: load a known index/archive/file and confirm the byte count and hex preview populate.
[ ] Raw Cache: export a loaded file and confirm the exported bytes match the loaded file length.
[ ] Raw Cache: on a disposable cache copy, replace a raw file and confirm a backup is created under cache-editor-backups before the write.
[ ] Raw Cache: reopen the replaced file and confirm the new bytes are readable.
[ ] Items: search a known item by numeric ID and confirm its decoded fields populate.
[ ] Items: search a known item by name and confirm the background index completes without freezing the UI.
[ ] Items: confirm name search results select and display the expected item definition fields.
[ ] Confirm definitions that fail to decode are counted as skipped instead of crashing the editor.
[ ] Confirm NPC/Object/Model/GFX/Animation/Sprite/Interface tabs remain disabled in this foundation slice.
[ ] Do not use raw replacement against the live server cache until the disposable-copy write/backup test passes.
[ ] From the normal Client Console shell, click Open RS3 CacheEditor and confirm the editor starts in a separate process and opens the Matrix3 root 830_cache automatically without showing the directory chooser.
[ ] Temporarily rename/remove the Matrix3 root 830_cache directory and confirm CacheEditor reports the supplied path is invalid and falls back to the directory chooser instead of failing silently.
[ ] While CacheEditor is open, click Open RS3 CacheEditor again and confirm a second editor process is not started.
[ ] Close CacheEditor, click Open RS3 CacheEditor again, and confirm it can be launched again without restarting the Matrix3 client.
[ ] Confirm CacheEditor startup/loading, main shell, tab area, Raw Cache controls/preview, Items tab, dialogs, lists, and text inputs use the dark palette with readable light text and no large default-white content areas.
[ ] Open Items and confirm item indexing starts automatically in the background while the UI remains responsive.
[ ] Type a partial item name without pressing Enter or clicking a Search button. Confirm results refresh automatically after the short debounce and each row shows the item name plus its ID in a taller Item Browser-style row.
[ ] Type an exact numeric item ID while background indexing is still running where practical. Confirm the exact definition can load directly without waiting for the complete name index.
[ ] Clear the Items search after indexing completes. Confirm the first usable cache items are shown in ascending ID order up to the visible-result cap and the result count/status remain readable.
[ ] Select several item results and confirm the right side shows a selected-item summary followed by grouped Summary, Models, Equipment, Options, Appearance, Variants, and Client Script Params cards rather than the old field/value JTable.
[ ] Resize CacheEditor narrower and wider. Confirm the detail pane tracks viewport width, long values stay reachable through vertical scrolling, and the result/detail split remains usable without horizontal clipping.
[ ] Confirm this UI pass does not enable structured item writes or alter existing Raw Cache read/export/replace behavior.
