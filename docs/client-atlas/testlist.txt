Client Atlas - Phase 1 test list

Quick/high-value checks
[ ] Clean/build Client with Java 8/Eclipse-compatible settings.
[ ] Run `game.atlas.ClientAtlasMain scan` from the Client project or repository root.
[ ] Confirm scan reports non-zero class, symbol, and relationship counts.
[ ] Confirm `.client-atlas/symbols.jsonl` contains a known obfuscated class, field, method, and constructor.
[ ] Confirm `.client-atlas/relationships.jsonl` contains DECLARES and at least one EXTENDS record; confirm IMPLEMENTS where a known implementing class exists.
[ ] Run `game.atlas.ClientAtlasMain status` and confirm metadata reopens and `Current fingerprint: true`.
[ ] Confirm `game/atlas/**` records are absent from generated symbol data.
[ ] Confirm normal `game.RS3Applet` launch ownership/configuration is unchanged.

Phase 1 gate checks after 1A.4
[ ] Run `game.atlas.ClientAtlasMain query "CLASS:game/Class1"` and confirm one exact symbol plus immediate relationships are returned as JSON.
[ ] Copy one METHOD or CONSTRUCTOR id from the returned DECLARES records and query that exact canonical id; confirm the owning DECLARES relationship is returned.
[ ] Run `game.atlas.ClientAtlasMain export "CLASS:game/Class1" docs/client-atlas/snapshots/class1.json` and confirm a compact UTF-8 JSON file is written.
[ ] Confirm query/export output includes `schemaVersion`, `clientFingerprint`, `queryId`, `indexCurrent`, relationship count/truncation state, the exact symbol, and immediate relationships.
[ ] Re-run query/export without rescanning and confirm the existing index reopens successfully.
[ ] Make a real client source change + rebuild (or otherwise change compiled client classes) and confirm query/export refuses the stale index until `scan` is run again.
[ ] If a queried class owns more than 200 stored immediate relationships, confirm output is capped and `relationshipsTruncated` is true while `relationshipCount` reports the full matching count.
