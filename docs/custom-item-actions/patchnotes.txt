- Added shared custom item action data authority for configurable item context actions.
- Moved the canonical config to `Server/data/items/custom-item-actions.properties`, matching Matrix3's existing server data layout.
- Client and Server now walk parent directories to resolve the same canonical config from normal Eclipse launch working directories; the duplicate repo-root `data/items/custom-item-actions.properties` was removed.
- Server now logs the resolved config path and number of loaded custom actions on first use so presentation-only success cannot hide a server config loading failure.
- Added server `CustomItemActions` registry with config-driven inventory/equipment/bank option routing; unconfigured items fall through to normal Matrix3 handlers unchanged.
- Added client `CustomItemActionConfig` presentation hook that applies configured inventory option labels and equipped-item option params to decoded item definitions without editing cache data.
- Option numbers are 1-based in config so a future editor can expose Option 1..N directly.
- Handler/action identifiers are stable data values (`BACKPACK`, `OPEN`, `EMPTY_TO_BANK`); Java method names are intentionally not stored in config.
- Rambler's backpack 21445 is the first configured item: Inventory Option 4 = Open, Equipment Option 1 = Open, Bank Option 7 = Open.
- Runtime evidence from the first test showed the client displayed `Open` while the server action did nothing; the split config location was corrected before changing Matrix3's normal inventory packet owner.
- Added a distinct `bank_inventory` context for interface 762 component 7 so bank inventory actions do not collide with the main bank item-container context.
- verified-static: 762:7 keeps stock options 1-5 for deposit amounts, option 7 Wear, option 8 Examine, and option 9 Deposit-All; native option 6 and option 10 are available without repurposing a stock action.
- Client bank-inventory presentation reads configured `bank_inventory` entries and adds missing native option slots for the clicked configured item.
- The client resolves the clicked item from Matrix3's dynamic interface child metadata; no Rambler item ID is hardcoded into the bank-menu hook.
- Server routing recognizes `bank_inventory` options 1-10. Configured Open validates the physical item from the player's inventory slot, while Empty to bank uses the existing player-owned backpack storage transfer.
- Added optional `bank_inventory.mode=EXPLICIT`. In explicit mode, a configured item's bank-inventory menu becomes an allowlist and unlisted stock option slots are hidden for that item only.
- Added stable `STOCK` action entries. These are presentation allowlist entries that deliberately return control to Matrix3's original ButtonHandler instead of replacing Deposit/Wear/Examine behavior.
- Explicit menu suppression now occurs in Matrix3's existing `Class592.method7012` menu-entry construction path before entries are grouped/inserted, avoiding stale grouped-menu bookkeeping while keeping the hook narrow.
- Rambler's explicit bank-inventory menu now allows only native slots 1, 6, 7, 8, and 10: Deposit, Open, Wear, Examine, and Empty to bank. Deposit-5, Deposit-10, Deposit-X/last amount, and Deposit-All are hidden only for the configured backpack item.
- The exact visual ordering of those five entries remains runtime verification because Matrix3's decompiled menu sorter groups interface option opcodes internally.
- Backpack contents remain player-owned persistent storage; this patch does not move storage ownership onto the physical item or change death persistence.
